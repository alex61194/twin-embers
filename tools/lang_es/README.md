# Spanish FireRed tools (work in progress)

Scripts that run **on the owner's PC** next to both ROMs (USA 1.0 and Spain BPRS rev 0).
They only print or write offsets and sizes, never ROM bytes. Their outputs stay on the PC.

- `align.py`, `align2.py`, `align3.py`: how much of the recipe matches between the two ROMs.
- `es_sizes.py`, `es_sizes2.py`: the Spanish length of each text symbol of the recipe (via pointers, then contiguous runs). They need the recipe's `entries-*.json`/`units-*.json` in `recipe/`.
- `es_events2.py` + `scrdis.py` + `script_ops.json`: Spanish layout of `event_scripts` (labels, pointer sites).
  `event_scripts_layout_us.json` is the label/reloc list of pret's `data/event_scripts.o` (USA build).
  `script_ops.json` is generated by assembling each macro of pret's `asm/macros/event.inc`.

Usage: `python3 -I es_events2.py "<USA rom>" "<Spain rom>"`. See STATUS.md and DISENO-event-scripts.md.

`event_scripts_layout_us.json` is not committed (too big for the audit limit). Regenerate it in the cloud or on Linux:
`apt install binutils-arm-none-eabi`, `python3 tools/bootstrap.py`, then in `build/upstream`:
`make tools && make build/firered/data/event_scripts.o`, and dump `arm-none-eabi-nm -n --defined-only`
(symbols t/d) and `arm-none-eabi-readelf -rW` (R_ARM_ABS32 offsets) into
`{"size": 421686, "us_start": 1440180, "syms": [[off, name]...], "relocs": [[off, type, sym]...]}`.

## Event scripts, Spanish object
1. `python3 -I es_events2.py "<USA rom>" "<Spain rom>"` writes `event_scripts_layout_es.json`
   (Spanish offset of every label, and every pointer site paired with its USA relocation).
2. `python3 gen_event_scripts_es.py event_scripts_layout_us.json event_scripts_layout_es.json event_scripts_es.s`
   writes the Spanish `data/event_scripts.s`: labels, `.space` and `.4byte` targets only, no ROM bytes.
   Fed the USA layout as both inputs it reproduces pret's object exactly (same 9,832 symbols, 9,954 relocations,
   421,686 bytes). With the Spanish layout: 420,310 bytes, 9,954 pointer sites (2 Nov 2026).

## Spanish recipe
3. `python3 -I gen_recipe_es.py "<USA rom>" "<Spain rom>" recipe es_sizes2.json event_scripts_layout_es.json recipe-es`
   maps every operation of the USA recipe to the Spanish ROM and writes `recipe-es/recipe-es.json`
   (offsets, lengths, CRC32s), a report and `placements.json`. It needs `builder/firered3ds_builder/`
   next to it or the checkout around it (the CRCs use the Builder's own interpreter).
   3 Nov 2026: all 6,734 files placed (engine ABI 0c92b443). Hand-decided cases are listed at the top of
   the script: English plural suffixes and the unreachable e-Reader scripts become empty, two trainer-card
   position bytes stay in the engine, Teachy TV's 4x2 Spanish closing banner goes into the English 8x2 slot.
   Two localized LZ pictures unpack to another size (credits "THE END" 448 -> 1536 bytes, Department Store
   tiles 6432 -> 6464): check them on the first Spanish build.
   The Spanish battle scripts are 6 bytes longer: Teeter Dance's loop gained a `jumpifhasnohp` at USA offset
   7638 (gamedata/asm/battle_scripts_1.bin, 12,548 -> 12,554 bytes, engine ABI 8b60009e). That entry and its
   unit were corrected by hand after finish_recipe_es.py, and `battle_scripts_1-00.json` gives the build the
   moved layout (`inserts` and `extra_sites`, read by gen_event_scripts_es.py). Redo both if the recipe is
   regenerated.
4. `python3 tools/lang_es/finish_recipe_es.py recipe-es.json event_scripts_layout_es.json` (in the checkout)
   writes `builder/firered3ds_builder/recipes/firered-ab8f6bfe.json`, its parts, the Spanish event-script
   layout (`event_scripts-NN.json`) and `pending.json`. While anything is pending the recipe's engine ABI is 0
   and the Builder refuses it.

## Spanish build
`make TWIN_LANG=es` uses the Spanish recipe. `tools/rex_objects.py` gives every text section the Spanish
length the recipe states (only sections without pointers, only for a non-USA recipe), and
`data/event_scripts.s` is rewritten with the Spanish layout (`event_layout_us.py` + `gen_event_scripts_es.py`).
The 3DS side then only accepts a pack built from the Spanish ROM (`3ds_data.c`).
