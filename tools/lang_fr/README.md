# French FireRed tools

Scripts that run **on the owner's PC** next to both ROMs (USA 1.0 and the French
one, rev 0, SHA-1 `fc663907256f06a3a09e2d6b967bc9af4919f111`). They only print or
write offsets, sizes and CRC32s, never ROM bytes; their outputs stay on the PC and
none of them is committed here.

The chain is the one `tools/lang_es` runs for the Spanish ROM, with the French ROM
as the target:

- `fr_sizes.py`, `fr_sizes2.py`: the French length of each text symbol (pointers
  first, then contiguous runs). They read the USA recipe's `entries-*.json` and
  `units-*.json`.
- `fr_events2.py` + `scrdis.py` + `script_ops.json`: the French layout of
  `event_scripts` (each label, each pointer site).
  `event_scripts_layout_us.json`, the label/reloc list of pret's
  `data/event_scripts.o`, is an input of it; `script_ops.json` is generated by
  assembling each macro of pret's `asm/macros/event.inc`.
- `event_layout_us.py`: dumps that `event_scripts_layout_us.json` from a pret build
  (`arm-none-eabi-nm -n --defined-only` for the symbols, `-readelf -rW` for the
  relocations), so it can be regenerated rather than shipped: it is 1.2 MB, above
  the audit's file limit.
- `gen_recipe_fr.py`: maps every operation of the USA recipe to the French ROM and
  writes the recipe (offsets, lengths, CRC32s), a report and the placements. It
  needs `builder/firered3ds_builder/` around it, since the CRCs are computed with
  the Builder's own interpreter.
- `finish_recipe_fr.py`: splits that recipe into
  `builder/firered3ds_builder/recipes/firered-fc663907.json` and its parts, adds the
  French `event_scripts-NN.json` layout, and writes `pending.json`. While anything
  is pending the recipe's engine ABI stays 0 and the Builder refuses it.

## Order

1. `python3 -I event_layout_us.py <pret build>` -> `event_scripts_layout_us.json`
   (or take it from a Linux/cloud job; do not commit it).
2. `python3 -I fr_events2.py <USA rom> <French rom> <event_scripts start>` ->
   `event_scripts_layout_fr.json`. The start is the French offset of the payload
   `event_scripts.bin` begins with; for this ROM it is `0x15f9d0`.
3. `python3 -I fr_sizes2.py ...` -> `fr_sizes2.json`.
4. `python3 -I gen_recipe_fr.py <USA rom> <French rom> <USA recipe dir> fr_sizes2.json event_scripts_layout_fr.json <out dir>`
   -> `recipe-fr.json`, a report and `placements.json`.
5. `python3 tools/lang_fr/finish_recipe_fr.py <recipe-fr.json> <event_scripts_layout_fr.json>`
   in the checkout -> the recipe under `builder/`, with `engine_abi` set only once
   nothing is pending.

## What had to be decided by hand

`gen_recipe_fr.py` keeps those cases at the top of the file, each with the reason
it could not be derived: the English plural suffixes the French game never appends,
the unreachable e-Reader scripts, the two trainer-card position bytes that stay in
the engine, and the Teachy TV closing banner.

Three sections were placed by CRC rather than by a search, because the French ROM
holds their data in another order:

- `battle_scripts_1.bin`: one 6-byte insertion at USA offset 7638 (12,548 ->
  12,554 bytes), the same shape as the Spanish recipe. `battle_scripts_1-00.json`
  carries the moved layout (`inserts`, `extra_sites`), which the event-script
  generator reads.
- `easy_chat.bin`: its two tables are swapped in the assembled file. The pins are
  `(0x3edeae, 16) -> (0x3e64da, 8)` and `(0x3ede88, 38) -> (0x3e64cc, 14)`.
- `strings.bin`, the credits: `(0x41d1b8, 32) -> (0x4156bc, 39)`.

`PINNED_SPAN` in `gen_recipe_fr.py` holds those four, and the run is only correct
when the pack's CRCs come out identical: `424295b0` for the battle scripts,
`f9749838` for the easy chat, `e660656d` for the strings.

## Build

`make TWIN_LANG=fr` uses that recipe. `tools/rex_objects.py` gives every text
section the length the recipe states, and `data/event_scripts.s` is rewritten with
the French layout. The 3DS side then only accepts a pack built from the French ROM
(`3ds_data.c`).
