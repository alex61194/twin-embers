# Security reporting

Security reports are welcome for malformed/corrupt packs, parser vulnerabilities,
unsafe recipe operations or path traversal, and Builder problems such as unsafe
output paths, unexpected overwrite, excessive allocation or execution of input.

Use the repository's private vulnerability-reporting channel if it is available
and accessible to you. Otherwise ask the owner, through your existing private
repository access, for a private reporting channel before disclosing sensitive
exploit details. No separate security contact address is designated here.

Include the affected commit, environment, affected parser/Builder operation,
impact and reproduction steps. Use a small, independently generated synthetic
input or describe the input structure in text. Explain the origin of the fixture;
do not send a real pack or game dump. Sanitize logs to remove private paths,
personal data, tokens and game content.

Never upload ROMs, `.pak`, game assets, extracted copyrighted material, saves or
game dumps to issues, reports, comments or attachments. Do not publish exploit
artifacts containing game content. The maintainer may request further synthetic
checks privately. A security report does not authorize a release, binary upload
or repository visibility change.
